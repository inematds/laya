Como funciona

Do texto à recomendação

A entrada é validada antes da inferência. A aplicação recusa texto que perderia tokens e mantém revisão humana em todas as respostas.

Ticket em PT→ Validação + Laya→ Revisão humana
Pré-requisitos

Prepare o ambiente

Python 3.10+ recomendado (testado com 3.12), Git, espaço para pesos e internet na primeira carga. GPU é opcional; CPU é o padrão.

Confira Python e Git

Use um ambiente virtual. Se optar por GPU, instale uma versão do PyTorch compatível com seu hardware.

# comando
python3 --version
git --version
Guia de uso · passo a passo

Da instalação ao primeiro ticket

Comandos para Linux/macOS. No Windows, ative o ambiente com .venv\Scripts\activate. O site publicado é o guia; a inferência acontece no servidor local.

1

Instale o projeto

O clone preserva o SDK oficial e adiciona a pasta practical.

git clone https://github.com/inematds/laya.git
cd laya
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -e . -r practical/requirements.txt
2

Prepare os pesos

Baixa e carrega somente multilingual. A primeira execução demora mais.

python3 -m practical download
3

Experimente pelo terminal

A saída é JSON. Nenhuma ação externa é executada.

python3 -m practical triage \
  --message "Fui cobrado duas vezes. Quero o reembolso."
4

Abra a mesa de triagem

Abra http://127.0.0.1:8765 no navegador da mesma máquina. Porta ocupada? Use --port 8875.

python3 -m practical serve --port 8765
# GPU opcional: --device vem antes do subcomando
python3 -m practical --device cuda serve --port 8875
5

Integre pela API

HTTP 422 indica entrada inválida; 503 indica modelo indisponível. Só use a previsão após HTTP 200.

curl -X POST http://127.0.0.1:8765/api/triage \
  -H "Content-Type: application/json" \
  -d '{"message":"Quero contratar o plano empresarial."}'
6

Meça e inspecione os erros

Compare a saída com os rótulos esperados e preserve as condições do teste.

python3 -m practical --device cuda evaluate --output avaliacao.json
python3 -m unittest discover -s tests/practical -v

Três erros preservados

Compra de 20 licenças foi para financeiro. Previsão do tempo e mensagem enviada por engano foram para suporte técnico.

O resultado mostra por que a política mantém revisão humana, inclusive em previsões confiantes.

A confiança de choice no SDK mede concentração da distribuição, não garantia de acerto. Churn neste esquema é ameaça explícita no texto. Nenhuma dessas saídas autoriza estorno ou cancelamento.
